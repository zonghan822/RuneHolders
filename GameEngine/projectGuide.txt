==========================================================
Project Guide
==========================================================

This guide explains how to set up, build, and run the project 
on a fresh Windows machine using Visual Studio 2022 and CMake.

----------------------------------------------------------
1. Prerequisites
----------------------------------------------------------
Before running any scripts, make sure the following are installed:

- CMake (v4.1.1 or above):
  https://github.com/Kitware/CMake/releases/download/v4.1.1/cmake-4.1.1-windows-x86_64.msi

- Git for Windows (v2.51.0 or above):
  https://github.com/git-for-windows/git/releases/download/v2.51.0.windows.1/Git-2.51.0-64-bit.exe

- Visual Studio 2022 (v17.10.4 or above).
  During installation, include "Desktop development with C++" workload.

- (Optional) OpenGL Extensions Viewer:
  Use this tool to verify your system supports OpenGL 4.5+.
  https://download.cnet.com/opengl-extensions-viewer/3000-18487_4-34442.html?ex=WLS-2202.0

- (Optional) .NET SDK (v8.0.0 or above):
  The build system will automatically detect or download a local copy
  of the .NET SDK if it is not found globally.

----------------------------------------------------------
2. .NET SDK Setup (Automatic)
----------------------------------------------------------
The engine uses .NET for C# scripting (GameScripts project).

When running CMake configuration, it will:

1. Check if .NET SDK is installed globally (using `dotnet --info`).
2. If found, use it directly for building C# scripts.
3. If not found, automatically download a portable SDK into:
   build/lib/dotnet/

CMake defines the variable:
  DOTNET_CMD → path to dotnet executable

At runtime, the engine automatically sets:
  DOTNET_ROOT = "<project>/build/lib/dotnet"
before loading managed assemblies, allowing .NET to locate its runtime
even when distributed without a global installation.

----------------------------------------------------------
3. Regenerating Visual Studio 2022 Solution
----------------------------------------------------------
Two scripts are provided to simplify project management:

- run.bat  
  * Cleans and recompiles the project if the executable is not found.  
  * Then runs the application.  

- clean.bat  
  * Deletes build artifacts and temporary files, resetting the project 
    to a clean state.

Usage:
- To build & run:  
  > run.bat

- To clean the project:  
  > clean.bat

----------------------------------------------------------
4. Regenerating Visual Studio 2022 Solution without Scripts
----------------------------------------------------------
If you want to regenerate the solution manually:

1. Open a command prompt (cmd) in the project’s root directory.
2. Create a build folder:
   > mkdir build
   > cd build
3. Run CMake to generate Visual Studio 2022 solution:
   > cmake .. -G "Visual Studio 17 2022" -A x64
4. Once finished, open the generated `.sln` file in the `build` folder.
5. Build from Visual Studio or run:
   > cmake --build . --config Debug

----------------------------------------------------------
5. Solution Structure
----------------------------------------------------------
The solution is named **RuneHolders**. It contains two main projects:

1. **Engine**
   - Location: `src/Engine/`
   - Type: Static Library (`Engine.lib`)
   - Purpose: Core game engine functionality.
   - Contains: window manager, graphics manager, event bus, physics system, 
     AI manager with A* pathfinding, audio integration (FMOD),
     FreeType font handling, .NET runtime hosting, ImGui backends, etc.
   - Dependencies (via `ImportDependencies.cmake`):
     * **GLFW** – window and input
     * **GLM** – math library
     * **GLEW** – OpenGL extension wrangler
     * **ImGui** – immediate mode GUI
     * **FMOD** – audio
     * **FreeType** – font loading
     * **stb_image** – texture/image loading
     * **.NET SDK** – for managed script integration (via `nethost` and `hostfxr`)
   - Output: `Engine.lib` in `build/projects/Engine/`

2. **Editor**
   - Location: `src/App/Editor/`
   - Type: Executable (`Editor.exe`)
   - Purpose: Application layer linking against `Engine.lib`.
   - Includes game logic and ImGui integration.
   - Output: Executable in `build/projects/App/Editor/`

3. **GameScripts (C#)**
   - Location: `scripts/GameScripts/`
   - Type: C# project compiled by .NET SDK into `GameScripts.dll`
   - Output: `build/scripts/GameScripts/`
   - Generated files:
       - GameScripts.dll
       - GameScripts.deps.json
       - GameScripts.runtimeconfig.json
   - Built automatically by CMake using `${DOTNET_CMD} build`.

⚠ IMPORTANT:  
After opening the solution in Visual Studio,  
**right-click on the `Editor` project and select “Set as Startup Project”**  
before pressing **F5 (Run)**.  
Otherwise Visual Studio will attempt to start the `Engine` project, which 
is a static library and has no executable.

----------------------------------------------------------
6. Project Settings & Configurations
----------------------------------------------------------
Both projects support standard Visual Studio configurations:

- **Debug**
  - Debug symbols enabled (`/Od`).
  - Defines: `_DEBUG`, `DEBUG`.

- **Release**
  - Optimizations enabled (`/O2`).
  - Defines: `NDEBUG`.

- **RelWithDebInfo**
  - Optimized with debug info (good for profiling).

- **MinSizeRel**
  - Optimized for smallest binary size.

FMOD DLLs and .NET runtime dependencies are copied automatically
based on the configuration.

----------------------------------------------------------
7. Assets
----------------------------------------------------------
- Assets (textures, shaders, sounds, fonts, scripts) are stored under:
  `assets/`
- During build, assets are copied into:
  `build/assets/`
- Engine defines a constant path `ASSETS_DIR_PATH` via CMake to locate assets
  relative to source.
- C# scripts are built into `build/scripts/` and loaded at runtime
  through the .NET runtime host.

----------------------------------------------------------
8. Additional Notes
----------------------------------------------------------
- Ensure `DOTNET_ROOT` is properly set by the engine before running.
  The path is automatically defined as:
    X:/RuneHolders/GameEngine/build/lib/dotnet
- The engine embeds .NET via `nethost.h` and `hostfxr.h`, loaded dynamically.
- For local SDK builds, no global .NET installation is required.
- If you wish to rebuild scripts manually:
  > dotnet build scripts/GameScripts/GameScripts.csproj -c Release
